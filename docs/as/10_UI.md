# 10 — The Play UI

The player-facing UI is a **new Vue 3 + Vuetify 3 app shell** inside Talemate's frontend build
(`talemate_frontend/src/play/`). It replaces Talemate's editor-style interface for playing. The old
interface stays reachable as **Workshop** (`?ui=workshop`, or Settings → Advanced → "Open
Workshop") and is never needed to play.

## 1. Clarity rules (enforced by tests)

| Rule | Meaning | Test |
|---|---|---|
| UI-CLARITY-01 | No engine vocabulary on any play screen: `packet, affordance, percept, LOD, claim, intent, handle, lane, schema, token, stage, event, actor, dossier` (whole words, any case, plural too). Exceptions: the Developer panel, and the Content screen, which is an authoring screen and may name record kinds (`dossier`, `affordance`, `actor`: the pack folders are called that, 09 §1) | `clarity.spec.js` scans every P8 screen's text, aria-labels, titles and placeholders; `words.spec.js` scans every string in `words.js` |
| UI-CLARITY-02 | No internal ids on screen (regex `\b(act|plc|anc|prt|itm|evt|clm|prp|pct)_\d{6}\b`); view refs (`p1`, `s4`…) are never shown either (UI-REF-01) | `clarity.spec.js`; `test_ui_fixtures.py` keeps ids out of the fixtures |
| UI-CLARITY-03 | Every control has words: its text, or an `aria-label` (an icon-only button has an aria-label; a tooltip may repeat it) | `clarity.spec.js` (every `button`, `a`, `[role=button]`, `[role=tab]`, input and textarea) |
| UI-CLARITY-04 | Status is never colour-only (every coloured state also has a word) | lane dots carry the word in `aria-label` (`play.spec.js`); the rest by the smoke checklist in `play/README.md` |
| UI-CLARITY-05 | Every panel title is a plain noun phrase: *Where you are · Your pack · Your body · People · Journal · Map* | `words.spec.js` (`PANEL_TITLES`), `panels.spec.js`, `clarity.spec.js` |
| UI-CLARITY-06 | Every error message says what happened and what you can do ("Your laptop brain isn't answering. The game will keep going on the desktop only — turns will be thinner.") | protocol tests: `message` is ≥ 20 characters, ends a sentence, no stack trace, no engine words (PROTO-08) |
| UI-SKULL-01 | The UI shows only what the player character knows | engine view tests (P7), the guide's inputs (`test_guide.py`) |

Visual defaults: dark theme, high contrast, body text 16 px, story text 18 px with 1.6 line height,
max story line length 72 characters, one accent colour for "your turn".

## 2. Screens

```
Connect ──► Home ──► New Life wizard (1 Who are you? · 2 What kind of world? · 3 House rules ·
   ▲          │        4 Build the world) ──► Play ◄──► Death
   └ lanes    ├──► Your lives (every session: play or delete) ──► Play
     down     ├──► Your characters & world (Content)
              └──► Settings (dialog, reachable everywhere)
```

**Which phase builds which screen.** P8: Connect, Home, Play (with every panel), Content (packs and
the validator), Settings, the Developer panel. P10: the New Life wizard and the Worldgen screen.
P12: Death, Worlds, and on the Content screen the import drop zone and document intake. Until its
phase, PlayApp shows `LaterScreen.vue` (`later-screen`: the sentence `TEXT.notBuilt` and a Back button
`later-back` → Home) for `wizard`, `worldgen`, `dead` and `worlds`. In P8 a run is made with
`as-engine new-scenario <scenario.yaml>` and opened with Continue or Load.

**Testable markup (every screen).** Each `data-testid` below is on a rendered DOM element. Nothing a
test clicks or reads is teleported (no `v-menu`, `v-dialog`, `v-tooltip` or `v-select` overlay around
it): menus are inline lists, choices are buttons, the settings dialog is an inline card PlayApp shows
over the screen. A tooltip may repeat what an `aria-label` or `title` already says.

### 2.1 Connect (`ConnectScreen.vue`, `data-testid="connect-screen"`) — P8
Shown on first launch and whenever `welcome.models_ok` is false. On mount it sends `models_list` and
`config_get`. Two cards (`LaneCard.vue`, also used by Settings → Models), side by side:

```
┌ Main model ─────────────────────────────────┐ ┌ Second model ─────────────────────────────────┐
│ Using: nemotron-cascade-2-30b-a3b           │ │ Using: nvidia-nemotron-3.5-lightning (not     │
│ Pick from LM Studio: (model) (model) …      │ │        saved yet)                             │
│ [ Test ]  Working — answered in 1.8 s.      │ │ Pick from LM Studio: (model) (model) …        │
│ Advanced ▸                                  │ │ [ Test ]  Not working — Not answering at …    │
└─────────────────────────────────────────────┘ └───────────────────────────────────────────────┘
                     [ Continue ]  (enabled when at least the Main model works)
```
Both models come from ONE list — the LM Studio server on this machine, which with LM Link on also
lists the other machine's models — so nobody types a model id or an address. Test ids: `lane-A-card`
(titled "Main model"; B's "Second model"), `lane-A-model` (plain text, not an input: "Using: <model>"),
`lane-A-model-option` (one per model the lane's `models` message lists; a click makes it the one in
use), `lane-A-advanced` ("Advanced": shows `lane-A-url`, the address text field, filled from `config`;
hidden until then — only needed without LM Link), `lane-A-test`, `lane-A-status` (the
`model_test_result` detail, with a word for ok / not ok) — the same for `B` — and `connect-continue`.
The model in use starts as the lane's configured one (`models.selected`) when LM Studio lists it;
otherwise it is the first listed model the other lane is not using, shown with "(not saved yet)"
until Test saves it. **Test** sends `config_set {patch: {lanes: {A: {base_url, model}}}}` with the
address and the model in use, then `models_test {lane}`. **Continue** is enabled when the last
test of lane A was ok or `welcome.models_ok` was true, and sends `get_state` (the server's `state`
says where to go). `other-tab-notice` shows `TEXT.otherTab` when a second tab was refused (§3).

### 2.2 Home (`HomeScreen.vue`, `home-screen`) — P8
On mount it sends `runs_list`. Big buttons, each with words: **Continue** (`home-continue`, only when a
run exists; names the newest run: "Continue — Owen Marsh, day 18, alive"; sends `run_load` for it),
**New life** (`home-new-life` → screen `wizard`), **Your lives** (`home-sessions` → screen `sessions`),
**Worlds** (`home-worlds` → screen `worlds`), **Your characters & world** (`home-content` → screen
`content`), **Settings** (`home-settings`: opens the dialog). P12 (D-79, D-102, CHEAT-12): an
**Enter a code** box — `home-code-label` (`TEXT.codeLabel`), a text field `home-code` and a button
`home-code-enter` (`TEXT.codeEnter`) that calls `store.enterCode(code)` → `code_enter {code}`; the
answer `code_result {accepted}` shows as `home-code-result`: `TEXT.codeAccepted` ("Accepted.") or
`TEXT.codeRejected` ("Nothing happens.") — nothing on the screen says what a code does (CHEATS §2).
An accepted code empties `store.pcs`, so the wizard asks for the list again.

### 2.2.1 Your lives (`SessionsScreen.vue`, `sessions-screen`) — P8 (the owner's sessions browser, RUN-12)
One simple list of every session ever played, and one easy delete that leaves nothing. On mount it
sends `runs_list`. Title "Your lives"; `sessions-back` returns Home. One `run-card` per run, newest
first (the server's order): the character's name, "day N", alive / dead, the difficulty's name, a
"Sandbox" tag if cheats were used, an "Ironman" tag, "ended" for an Ironman life that is over
(`final`), "last played …". `run-card-load` (sends `run_load`; not shown on an ended life — it can
be deleted, not played on). `run-card-delete` sends nothing: it opens the card's confirmation, the
question `run-card-delete-question` "Delete Owen Marsh's story? This can't be undone." with
`run-card-delete-confirm` ("Delete", sends `run_delete`) and `run-card-delete-cancel` ("Keep it",
closes the question). No second step, no "deep" option: every delete is the complete one. With no
runs: `sessions-empty` "No lives yet. Start one with New life." When `run_deleted` arrives the card
goes at once and the client forgets everything it held for that run (§4).

### 2.3 New Life wizard (`WizardScreen.vue`, `wizard-screen`) — P10
Four steps over one draft kept in the store (`store.wizard`), so Back, a cancelled build or a refused
world comes back to the same choices. On mount it sends `pcs_list` unless `store.pcs` already holds
cards.

Top: `wizard-step-1` … `wizard-step-4`, each showing its title (`TEXT.wizardSteps`: "Who are you?",
"What kind of world?", "House rules", "Build the world") with `data-state` = `done` | `current` |
`todo`. Bottom: `wizard-back` (step 1: back to Home; else the step before), `wizard-next` (steps 1–3;
`disabled` while the step is not complete) and, on step 4, `wizard-start`.

1. **Who are you?** One `pc-card` (`PCCard.vue`) per `store.pcs` card, in the server's order, in the
   CMG §61 format:
   ```
   ADDISON FLORES — Small, warm, physically competent runner-scavenger
   Survives by  Getting to places others can't reach, trading what she finds
   Starts as    Adjacent — known and valued by local groups, not embedded
   Note         Her trade economy requires someone to trade with.
   ```
   Test ids inside a card: `pc-card-name` (display_name), `pc-card-identity` (one_line_identity),
   `pc-card-survives` (`TEXT.survivesBy` + survives_by), `pc-card-starts` (`TEXT.startsAs` +
   starts_as), `pc-card-note` (`TEXT.note` + note) and, when the card has one, `pc-card-age` (its
   world_age_note). A click selects it (`aria-pressed="true"`; draft.pcRef = its ref) and unselects the
   rest; `wizard-next` needs a selection. **Import a character** and **Make one quickly** arrive with
   P12 (`pc-import`, `pc-quickmake`; not shown before).
2. **What kind of world?** Buttons with words (`aria-pressed="true"` on the chosen one):
   - `difficulty-option-<value>` for each Difficulty in order (bitch_mode, easy, normal, realism,
     actually_hell, fuck_you): the tier's name (as the Home run card shows it) and its CMG description
     verbatim (`DIFFICULTY_HELP[value]`, 11_SETTINGS §1.1). Default `normal`.
   - `era-option-<value>` for early, established, mature: `ERA_TEXT[value]` = {label, help, days: [lo,
     hi]} (days = the engine's `contracts.settings.ERA_DAYS_RANGE`). An era whose days do not overlap
     the chosen character's `world_age_days` is `disabled` and shows `era-reason-<value>` = the card's
     `world_age_note` (WG-34: the wizard never offers a world the character cannot live in). Default
     `mature`; when it does not fit, the first era (in that order) that does. Coming back to step 2
     with another character re-applies the rule when the chosen era no longer fits.
   - `detail-option-<value>` for each WorldDetail in order: `DETAIL_TEXT[value]` = {label, minutes},
     shown as the label and `TEXT.buildTime(minutes)` ("About 15 minutes to build"). Default `standard`.
   - `days-input`: optional whole number, with `days-hint` = `TEXT.daysHint(lo, hi)` for the allowed
     range (the chosen era's days intersected with the character's; the era's alone when the character
     has none). A value outside it, or not a whole number, shows `days-error` (`TEXT.daysRange(lo, hi)`)
     and keeps `wizard-next` disabled. Empty = drawn inside the range.
   - `seed-input`: optional whole number ≥ 0 (anything else shows `seed-error`, `TEXT.seedHelp`, and
     keeps Next disabled). Empty = random.
   (P12 adds the **Make a new world / Use a saved world** toggle, `world-source-new` /
   `world-source-saved`, with `world-card` items from `worlds_list`.)
3. **House rules** (`house-rules`): one `wizard-setting` row (`data-field` = the field) per common
   setting — `save_mode`, `turn_depth`, `narration_length`, `intensity`, `show_mechanics` — with the
   label and help of `SETTINGS_TEXT[field]` and a button per choice, `wizard-setting-<field>-<value>`
   (`aria-pressed` on the chosen; defaults = RunSettings' defaults). `more-options-toggle` shows the
   rest the same way: `narration_person`, `narration_tense`, `pc_voice`, `read_aloud` (`true` /
   `false`), `wild_card` (P12, D-102: `true` / `false`, default Off) and `autosave_ring` (a number
   field `wizard-setting-autosave_ring`, 1–50). P10 adds
   `SETTINGS_TEXT.save_mode` = {label 'Save mode', help, choices {free: 'Free', ironman: 'Ironman'}}.
4. **Build the world**: `wizard-summary` names the character, the difficulty, era and world detail
   (their labels), the days since the Fall and the seed when given, and Free or Ironman.
   `wizard-start` calls `store.newLife(pcRef, settings)` → `run_new {pc_ref, settings}` with settings =
   {difficulty, era, world_detail, save_mode, every house rule (all of them, defaults included),
   days_since_fall and seed only when given}; the screen becomes `worldgen` at once.

### 2.4 Worldgen (`WorldgenScreen.vue`, `worldgen-screen`) — P10
The loading bar (§2.10) for the worldgen job, and under it the older line from `worldgen_progress`:
`worldgen-label` (the stage label), `worldgen-progress` ("NN%") and `worldgen-eta`
(`TEXT.barEta(eta_s)`, hidden without an estimate). **Cancel** (`worldgen-cancel`) sends
`worldgen_cancel`; its answer (`state {screen 'wizard'}`) returns to the wizard with the draft kept —
nothing half-built is left behind. A world that cannot be made arrives as an `error` (PlayApp's
notice shows its sentence: "Hal Brandt cannot survive the start this world gives them at Normal. Try
one difficulty lower, another character, or another era.") followed by `state {screen 'wizard'}`:
the wizard again, choices kept. When the world is ready, `run_loaded` opens Play (§4).

- **TopBar** (`TopBar.vue`): `topbar-pc-name`, `topbar-day` ("Day 18"), `topbar-clock` (time, part of
  day, weather), `sandbox-badge` (only in a Sandbox run: "Sandbox"), `lanes-status` with `lane-dot-A` /
  `lane-dot-B` (`aria-label` = `"<LaneStatus.label>: working"` or `": not answering"`, the same in the
  tooltip), `topbar-save` (hidden in Ironman; reveals `save-name` + `save-confirm`, which sends
  `run_save {slot_name}`; the `saved` answer shows `saved-notice` "Saved as “…”."), `topbar-settings`
  (opens the dialog), `topbar-quit` ("Save & quit": `run_close`; the game autosaves after every turn).
- `load-notice` shows the `run_loaded` notices until `load-notice-dismiss`.
- **Where you are** (`WherePanel.vue`, `where-panel`, title `panel-title`): `loc-place-name`,
  `loc-area-name` (when set), `loc-description-line` ×1–6, `loc-seen-item` ("hand pump — rusted"),
  `loc-person` (label + status words), `loc-exit` (label + state words + "leads to …", or a plain "not
  known yet" — never the word "unknown"), `loc-danger`, `loc-noise`, `loc-look-closer` (emits `send`
  with Do `TEXT.lookCloser`; the screen submits it). **Built entirely by code from the PC's
  perception** (`narration/location.py`) — never by the model.
- **Story** (`StoryPanel.vue`, `story-panel`): one `story-entry` per story entry, `data-kind` =
  narration | player | guide | notice | cheat | willis | doom | voice | voice_after, in server order. Player entries are right-aligned and
  start with `TEXT.modeLabel[mode]` ("You do:", "You say:", "You ask:"); guide answers start with
  `TEXT.guideLabel` ("Guide:") as a side note; narration entries are the text alone; notices small and
  grey; cheat entries in a distinct monospace style; willis entries (D-105: his lines at a death)
  start with `TEXT.death.willis` ("Willis") and stand apart from the narration; the Doom's entries
  (D-106: doom — the frozen moment's scene lines —, voice, and voice_after after the death) stand
  apart too, the voice ones in their own style, with no name before them.
  - `turn-progress` (only while a turn runs) with `turn-progress-label` (the friendly label) and
    `turn-elapsed` (seconds); `turn-stop` only while the stage is below 12 ("Locking it in…"), sends
    `turn_cancel`. P10: under it, the loading bar (§2.10) for the turn and the quiet hours before it.
  - `rejection-banner` for `turn_rejected`: the plain reason and the clarify question if any.
  - `mechanics-receipt` only when the view carries receipt lines (Show dice ≠ off and something was
    rolled): one line per roll, "Climb over: success with a cost", and for a defence against a grab
    or a shove "Resisting grab: failure" (P10); Full adds "(needed 6 or less, rolled 5)".
- **Input** (`InputBox.vue`, `input-box`; P12, D-103 — the owner: "at most Act: Say: Cheat: ... fill-in
  friendly ... it's gotta know who we're talking to"): up to three labelled fields (`TEXT.inputLabel`
  Act / Say / Cheat, shown beside each and as its `aria-label`), any of them filled, sent together —
  `input-act` (placeholder `TEXT.placeholder.act`, "What do you do?"), `input-say`
  (`TEXT.placeholder.say`, "What do you say?") with `say-to-chip` ×n under it ("Anyone who can hear"
  + each person in the room, `aria-pressed` on the chosen; the view's `say_to` is chosen first when
  present, else "Anyone who can hear"; a name at the start of the words also picks the listener on
  the server), and `input-cheat` (`TEXT.placeholder.cheat`, "Anything at all.") shown ONLY while
  `view.console` is true (CHEATS §2).
  Enter in any field sends, Shift+Enter is a new line; `input-send` (disabled while a turn runs) sends
  `turn_compose {act, say, cheat, to: [the chosen chip's ref] or []}` and clears the fields. Act and
  Say together are one moment (the act, and the words said while doing it). **Ask** is not a field:
  the `input-ask` button ("?", `aria-label` `TEXT.askLabel` "Ask the guide") opens `ask-text`
  (placeholder `TEXT.askPlaceholder`, "Ask the guide anything — it won't cost a turn") + `ask-send`,
  which sends `turn_submit {mode: 'ask', text, suggestion_ref: null, addressee_refs: []}` (the guide;
  no turn passes). `suggestion-chip`
  ×≤6 (the view's suggestions): a Do chip is sent at once (`turn_submit {mode: 'do', text: '',
  suggestion_ref}`); a Say chip puts its `suggestion_ref` aside and waits for the words in
  `input-say`, then sends `turn_submit {mode: 'say', text, suggestion_ref, addressee_refs: []}`. When
  the character is dead the fields are disabled, the chips are gone and `input-dead` says
  `TEXT.deadInput`. `input-act` shows `store.composeText` (the pack's item actions fill it).
  Suggestions are the character's own options ("Hide behind the counter"), never story prompts or plot choices (UI-SUG-02),
  and no two chips read the same (P10: with three of the dead in front of you, one "Axe to a
  shambling figure's head" chip — the nearest — not three).
- **Right tabs**: `tab-pack`, `tab-body`, `tab-people`, `tab-journal`, `tab-map` (buttons with
  `role="tab"`, labelled with the panel titles; Your pack first). Each panel takes the view as its one
  prop, shows its title in `panel-title`, and emits `compose` (text for the Do box) — never a state change.
  - Your pack (`PackPanel.vue`, `pack-panel`): `pack-hands-item`, `pack-worn-item` (name, "× n" when
    more than one, condition word, detail), `pack-container` (per container, nested ones too: its
    item, "used/max bulk" and a bar with that as its aria-label), `pack-container-item` (a non-container
    inside), `pack-load` ("Load: moderate (9.4 kg)"). A click on an item shows its `item-action`
    buttons inline; one emits `compose` with `"<action> the <item name>"` ("Put away the crowbar",
    "Use the bandage") — the UI never changes state directly.
  - Your body (`BodyPanel.vue`, `body-panel`): `body-wound` (where, what, severity word, bleeding word,
    "treated" / `TEXT.notTreated`), `body-need` (name + word, and a bar whose aria-label is
    "Thirst: noticeable"), `body-impairment`, `body-resolve` ("Resolve 4/6 — shaken", `title` =
    `TEXT.resolveHelp`: "Your nerve. At zero you can only flee, freeze, surrender or protect someone you
    love."), `body-status`.
  - People (`PeoplePanel.vue`, `people-panel`): `person-card` per person you know: name or description,
    your feelings in words ("you trust them", "you owe them"), last seen, what you know, promises
    between you, alive / dead / `TEXT.aliveKnown.unknown`. (Pinning a line to a voice, DOS-05, has no
    protocol action yet: later.)
  - Journal (`JournalPanel.vue`, `journal-panel`): `journal-promises-made`, `journal-promises-owed`,
    `journal-goals`, `journal-rumours`, `journal-lessons`, `journal-dead`, `journal-reputation`; an empty
    section says `TEXT.nothingYet`.
  - Map (`MapPanel.vue`, `map-panel`): `map-place` per known place (label, `TEXT.youAreHere` on the
    current one, visited or not, exits known, travel time when given).
- `dev-panel` below everything, only when the run's `dev_mode` setting is on (§2.9).

Responsive: ≥ 1280 px three columns (320 | flexible | 360); 900–1279 px Story + right tabs, with

### 2.6 Death (`DeathScreen.vue`, `death-screen`) — P12 (BUILT, D-105, D-106)
Shown from `store.death` (the `death` message; the server sends it twice after a death: at once, with
Willis's lines and the Voice's words from the Doom, then with the Voice's last word). `death-title` (`TEXT.death.title(pc_name)`, "Owen Marsh is dead."),
`death-when` (`TEXT.death.when(day, time_text)`), `death-cause` (the cause as the dead person felt it).
**Willis** — the owner: "When you die, regardless of Wildcard activation, you see Willis. He mocks and
roasts you joyously over your mistakes." — `death-willis` (headed `TEXT.death.willis`): while
`willis_pending` the line `death-willis-pending` (`TEXT.death.willisArriving`, "Somebody is

`death-willis-line` per line he says. **The Voice** (D-106; no name, anywhere) — `death-voice`
(headed `TEXT.death.voice`, "In the dark"; shown when there are words or more to come): one
`death-voice-line` per paragraph, and while `voice_pending` the line `death-voice-pending`
(`TEXT.death.voicePending`, "It isn't finished with you."). `death-last-turns` ×≤3 (under
`TEXT.death.lastMoments`), `death-contributing` ×≤5 (under `TEXT.death.choices`: choices from your
record). `death-reveal-button` (`TEXT.death.reveal`, "Show me everything") → `death-reveal-warning`
(`TEXT.death.revealWarning`, with `death-reveal-confirm` / `death-reveal-cancel`); confirm sends
`death_reveal` (`store.revealDeath()`), and the answer's `truth_reveal` fills `death-reveal`
(`death-reveal-line` ×n; the button is gone). `death-load` (`TEXT.death.load`; hidden in Ironman) →
Home; `death-new-world` (`TEXT.death.newWorld`) → the New Life wizard. In Ironman `death-ironman`
says plainly `TEXT.death.ironman`: "This life is over. The world is still out there."
`death-new-life-here` (a new character in this same run, RUN-07) and `death-fresh-world` ("Start
fresh in this world", worlds) arrive with those P12 items. Willis's lines also stand in the story
(StoryEntry kind 'willis'), set apart from the narration.

### 2.6.2 The Doom (`components/DoomOverlay.vue`, `doom-overlay`) — P12 (BUILT, D-106)
The owner: everything freezes — the dust, the air, the thing you're fighting; about three seconds
later the lights go out, even the sun; footsteps; Willis; something like a giant mantis takes him, a
quarter of a second; then nothing, just you; then the Voice (`docs/as/sources/THE_VOICE.md`). The
`doom` message (sent before the turn's `turn_result`, `service/voice.py` VOICE-01) sets `store.doom`;
PlayApp shows the overlay above whatever screen is up (a death in the same turn has already opened
the death screen beneath it). Full screen, black but for the faintest glow. One `doom-beat` per beat
shown (`data-kind` = scene | willis | snatch | voice), in order: the first at once, each next after
`beatDelay(previous, beat)` (`doom.js`: its `pause_ms` plus 35 ms per character of the previous
beat, at most 20 s). Willis's beats start with `TEXT.death.willis` ("Willis: "); the Voice's stand in
their own style with no name. `doom-next` (`TEXT.doom.next`, "Go on"; a click anywhere does the same)
shows the next beat at once; after the last it lets the moment go (`store.dismissDoom()`). The same
beats stand in the story (kinds doom, willis, voice).

### 2.6.1 Worlds (`WorldsScreen.vue`, `worlds-screen`) — P12

with **Start a new life here** (`world-start`), **Export** (`world-export`, downloads

### 2.7 Your characters & world (`ContentScreen.vue`, `content-screen`) — P8 (validator), P12 (imports)
On mount it sends `packs_list`. Packs (`pack-row`): name, version, "N records", description, and
`pack-validate` → `content_validate`; the report appears under that pack: "No problems found." or one
`content-report-error` / `content-report-warning` line each ("actors/mara_voss.yaml —
voice.would_never_say needs at least 3 lines (it has 1)"). `content-back` → Home. P12 adds the import
drop zone (`content-import-drop`) and **Turn a document into a record** (`intake-start`: choose Person /
Playable character / Faction / Lore, drop a .md/.txt/.docx; shows progress per section; the draft
opens for review; nothing becomes canon until you move it in).

### 2.8 Settings (`SettingsDialog.vue`, `settings-dialog`) — P8
An inline card PlayApp shows over the current screen while `store.settingsOpen`. Tabs (buttons with
`role="tab"`): `settings-tab-models` (the two lane cards of §2.1), `settings-tab-gameplay`,
`settings-tab-advanced`; `settings-close`.
- Gameplay: one `setting-row` (`data-field` = the field) per field of `store.changeable` except
  `dev_mode`, in that order (11_SETTINGS §1.2): the label, the help sentence and a button per choice,
  `setting-<field>-<value>` (booleans as `true` / `false`), from `SETTINGS_TEXT`. `autosave_ring` is a
  number field `setting-autosave_ring`. A choice sends `settings_set {patch: {<field>: value}}`;
  the number field sends on `change`. Without a run: `settings-no-run` says the settings belong to a life.
- Advanced: `setting-dev_mode-true` / `-false` (`settings_set`), background thinking
  `setting-background-true` / `-false` (`config_set {patch: {background_cognition}}`), and
  `open-workshop` (a link to `?ui=workshop`).

### 2.9 Developer panel (`DevPanel.vue`, `dev-panel`, only with Developer mode) — P8
A bottom drawer: one tab per kind of record — `dev-tab-trace` (the stage timeline), `dev-tab-intents`
(each person's choice), `dev-tab-packets` (the minds' answers), `dev-tab-events`, `dev-tab-gate` (the 58
bits), `dev-tab-errors` (repairs), `dev-tab-calls` (raw model traffic). A tab sends `dev_get {what,
turn_index: null}` (the current turn) and lists the answer's rows as `dev-row` (each row's JSON). This
is the one place engine vocabulary is allowed.

### 2.10 The loading bar (`LoadingBar.vue`, `loading-bar`) — P10 (progress v2, `service/progress.py`)
Every long job announces its whole plan, then where it is, live (PROG-01..06). The bar draws it: the
plan's phases in order with the current one lit, the step's plain label, how far along, and one
rotating line about the step — the way a thinking indicator says "Rolling…", but about THIS step.
It renders while `store.bar` is set and `store.bar.kind` is in its `kinds` prop: the Worldgen screen
passes `['worldgen']`; the Play screen shows one under `turn-progress` with `['turn', 'quiet_hours']`.
- `bar-title`: the plan's title ("Making your world", "Your move", "Everyone else catches up").
- One `bar-phase` per phase, in order: text = its label, `data-phase` = its id, `data-state` =
  `done` (before the current phase) | `current` | `todo`; the current one has `aria-current="step"`.
  Before the first step every phase is `todo`.
- `bar-step`: the current sub-phase's label, or the phase's label when the step has no sub-phase (not
  shown before the first step).
- `bar-fill`: `role="progressbar"`, `aria-valuemin="0"`, `aria-valuemax="100"`, `aria-valuenow` = pct
  rounded, `aria-label` = `TEXT.barProgress`; `bar-pct`: "NN%" (pct rounded).
- `bar-count`: `TEXT.barCount(done, total)` ("2 of 7") only when the step carries counts (worldgen's
  history and people, the quiet hours; never a turn).
- `bar-elapsed`: `TEXT.barElapsed(elapsed_s)` ("12 s so far"); `bar-eta`: `TEXT.barEta(eta_s)` ("About
  40 s left", from 60 s up in minutes: "About 3 min left") only when eta_s is not null.
- `bar-quip`: one line from the plan's quips (below), only when the step has any.
- `bar-detail`: the step's detail, only when there is one (developer mode, PROG-05).
Quips (`quips.js`, pure functions, PROG-07): `quipLines(quips, kind, phase, sub)` = the first
non-empty list among the keys `'<kind>.<phase>.<sub>'`, `'<kind>.<phase>'` and `'<kind>'` of `quips`
([] when none). `nextQuip(lines, recent, random = Math.random)` = a line that is not one
of the last k lines in `recent` (the lines shown so far this job, oldest first; k = min(3,
lines.length - 1)): candidates[Math.floor(random() x candidates.length)] with candidates in `lines`
order; null when `lines` is empty. `QUIP_MS` = 2500. The bar shows a new line as soon as the step
(phase or sub-phase) changes, then every QUIP_MS while it stays; `recent` starts empty with each plan.
The quip is never alone: `bar-step` is always on screen with it (it is about the step, never about the
world — the lines are content, `ui/quips.yaml`, and say nothing of who is near or how a roll went).

**PlayApp.vue** takes an optional `store` prop (tests pass one); without it, it builds
`createPlayStore(createSocket(socketUrl(import.meta.env.VITE_TALEMATE_BACKEND_WEBSOCKET_URL,
window.location.href)))`. It calls `provide('playStore', store)`; screens, the top bar, the input box,
the settings card and the developer panel `inject('playStore')`. Panels take a single prop (`view`)
and emit `compose` (text for the Do box) or `send` ({mode, text}). It shows `error-toast` with the
error's message and `error-dismiss` (→ `store.clearError()`) for every error except `other_tab`
(Connect shows that one). `App.vue` renders `PlayApp` unless the URL has `?ui=workshop`.

**words.js** exports `PANEL_TITLES`, `BANNED_WORDS` (UI-CLARITY-01's list), `ID_PATTERN`
(UI-CLARITY-02's regex), the word functions of §5 (`conditionWord`, `resolveWord`, `impairmentWord`,
`bleedingWord`, `severityWord`, `loadWord`, `noiseWord`, `needWord`), `DIFFICULTY_TEXT`, `SETTINGS_TEXT`
(per changeable run setting: `label`, `help`, `choices` {value: words}, none for `autosave_ring`) and
`TEXT` (every other string; the specs read `TEXT.placeholder`, `TEXT.otherTab`, `TEXT.notBuilt`,
`TEXT.lookCloser`, `TEXT.deadInput`, `TEXT.modeLabel`, `TEXT.guideLabel`, `TEXT.notTreated`,
`TEXT.resolveHelp`, `TEXT.aliveKnown`, `TEXT.nothingYet`, `TEXT.youAreHere`). No component hard-codes a
player-facing string. P10 adds `DIFFICULTY_HELP` ({value: the CMG description}), `ERA_TEXT` ({value:
{label, help, days: [lo, hi]}}), `DETAIL_TEXT` ({value: {label, minutes}}), `SETTINGS_TEXT.save_mode`
and in `TEXT`: `wizardSteps` (the four step titles), `wizardBack`, `wizardNext`, `wizardStart`,
`survivesBy`, `startsAs`, `note`, `moreOptions`, `buildTime(minutes)`, `daysHint(lo, hi)`,
`daysRange(lo, hi)`, `seedHelp`, `summary` (the summary's line labels), `worldgenCancel`,
`barProgress`, `barCount(done, total)`, `barElapsed(s)` and `barEta(s)`.

**socket.js.** `socketUrl(envUrl, pageUrl)`: Talemate's rule — `envUrl` when it is a `ws://` or
`wss://` URL (with a `0.0.0.0` host replaced by the page's hostname), else `ws://<page host>:5050/ws`.
`createSocket(url, {WebSocketImpl = WebSocket, delays = [1000, 2000, 4000, 8000, 10000]})` connects at
once and returns `{status, send(msg), on(action, fn), off(action, fn), onStatus(fn), close()}`:
- `status`: `'connecting'` → `'open'` → `'closed'` (and again), or `'other_tab'` for good.
  `onStatus(fn)` is called with each new status.
- `send({action, ...fields})` sends `{type: 'as_game', action, ...fields}` as JSON; while not open, sends
  are queued and flushed in order on open.
- `on(action, fn)` calls `fn(data, message)` for every received message whose `type` is `as_game` and
  whose `action` matches (`'*'`: every `as_game` message). Every other type is ignored, with one
  exception: **one tab at a time.** Talemate 0.39.0 (`server/api.py`) accepts a single frontend
  connection. A second tab or window receives `{"type": "system", "status": "error", "message":
  "Another Talemate frontend is already connected. …"}` and is closed. The socket then sets status
  `'other_tab'` and never reconnects; the store shows `TEXT.otherTab` (*"The game is already open in
  another tab or window. Close that one, then reload this page."*) on the Connect screen. The Workshop
  (`?ui=workshop`) and the Play UI therefore cannot be open at the same time either.
- After an unexpected close it reconnects after 1 s, 2 s, 4 s, 8 s, then every 10 s; an open resets
  the backoff. `close()` stops for good.

## 4. Store contract (`store.js`)

`createPlayStore(socket, {download} = {})` returns one `reactive` object: state, actions and
client-only helpers. It sends `hello {client_version: CLIENT_VERSION}` whenever the socket's status
becomes `'open'` (and at creation when it already is). `download(filename, dataB64)` saves a file (the
default makes a browser download; tests pass their own).

State: `screen` ('connect' until the first `welcome`; then 'home' | 'play' | 'content' | 'wizard' |
'worldgen' | 'dead' | 'worlds' | 'sessions'), `connected`, `busy`, `serverVersion`, `modelsOk`, `hasRuns`, `runId`,
`lanes` (LanesView), `models` {A, B} (the `models` data), `laneTests` {A, B} (the `model_test_result`
data), `config`, `runs`, `pcs`, `packs`, `contentReport`, `view` (PlayView), `story` (StoryEntry[]),
`progress` ({turnIndex, stage, label, pct, elapsed} | null), `rejection` ({reasonCode, message,
clarify} | null), `settings` (RunSettings), `changeable`, `ironman`, `sandbox`, `notices`, `death`,
`doom` ({beats} | null; P12, D-106), `worldgen`, `worlds`, `devData` ({<what>: dev_data}), `cheatShimmer` (true for 1.2 s after
`cheat_activated`), `error` ({code, message} | null), `saved`, `composeText`, `mode` ('do' | 'say' |
'ask'), `settingsOpen`; P10: `bar` (the loading bar, below) and `wizard` (the New Life draft: {step
1..4, pcRef null, difficulty 'normal', era null (the default rule of §2.3), detail 'standard', days
'', seed '', rules: the house-rule fields with RunSettings' defaults, more false} — made at creation
and again by every `run_loaded`, kept otherwise, so a cancelled or refused build returns to it).

Actions → messages (each sends exactly one message): `hello()`, `getState()` get_state, `listModels()`
models_list, `testLane(lane)` models_test, `getConfig()` config_get, `saveModels(patch)` config_set,
`listRuns()` runs_list, `loadRun(runId, saveSlot = null)` run_load {run_id, save_slot}, `closeRun()`,
`deleteRun(runId)` run_delete {run_id}, `save(slotName)` run_save, `submit(mode, text, {suggestionRef = null,
addresseeRefs = []})` turn_submit {mode, text, suggestion_ref, addressee_refs} (clears `rejection`),
`turnCompose({act = '', say = '', cheat = '', to = []})` turn_compose {act, say, cheat, to} (P12, D-103;
clears `rejection`),
`cancelTurn()` turn_cancel, `getView()`, `getStory()`, `getSettings()`, `setSettings(patch)`
settings_set, `devGet(what, turnIndex = null)` dev_get {what, turn_index}, `listPacks()`,
`validatePack(packId)` content_validate; for later phases `newLife(pcRef, settings, worldId = null)`
run_new (screen 'worldgen'), `cancelWorldgen()`, `listPcs()`, `revealDeath()`, `newLifeHere(pcRef)`,
`listWorlds()`, `exportWorld(worldId)`, `importFile(file)`, `startIntake(file, kind)`,
`importWorld(file)` (the file read as base64). Client-only (no message): `go(screen)`,
`openSettings()`, `closeSettings()`, `compose(text)` (mode 'do' + composeText), `clearError()`,
`dismissNotices()`, `dismissDoom()` (doom null; P12).

Message handling: `welcome` → serverVersion, modelsOk, hasRuns, screen; then on 'play' it sends
get_state, view_get, story_get, settings_get and on 'home' runs_list. `state` → screen (except that a
client-only screen — content, worlds, wizard, sessions — is not left for 'home'), runId, busy (not
busy → progress null). `models` / `model_test_result` → models / laneTests by lane. `config` →
config. `runs` → runs, hasRuns. `run_deleted` (RUN-12) → that run leaves `runs` at once; when it is
`runId`: runId, view, death null, story [], notices [], composeText '' — and nothing of it is kept
anywhere else (the client stores no run's story, words or drafts outside this object). `run_loaded` → runId, ironman, sandbox, settings, notices, screen 'play', story [],
rejection / death / doom / progress null, then it sends settings_get. `view` → view, lanes, sandbox.
`story` → story (the server's story is the truth: turn results and guide answers arrive with a new
`story`). `turn_progress` → busy, progress. `turn_result` → view, lanes, progress null, rejection null.
`turn_rejected` → rejection, progress null. `saved` → saved. `settings` → settings, changeable.
`dev_data` → devData[what]. `packs`, `content_report`, `pcs`, `worlds` → their fields. `death` →
death, screen 'dead'. `doom` → doom {beats} (P12, D-106). `cheat_activated` → cheatShimmer, sandbox true, a cheat entry appended to the
story ({turn_index: the view's, kind 'cheat', text: persona_line, mode null}); `cheat_result` → the
same entry. `worldgen_progress` → worldgen, screen 'worldgen'. `world_file` → download. `lanes_status`
→ lanes. `error` → error. Socket status 'other_tab' → error {code 'other_tab', message TEXT.otherTab},
screen 'connect'.
P10, the loading bar: `progress_plan` → bar = {jobId: job_id, kind, title, phases (as sent), quips,
phase null, phaseIndex -1, sub null, subLabel null, done null, total null, pct 0, elapsed 0, eta null,
detail null}; `progress` whose job_id is the bar's → phase, phaseIndex, sub, subLabel, done, total,
pct, elapsed (elapsed_s), eta (eta_s), detail (another job's progress is ignored); `progress_done`
whose job_id is the bar's → bar null; `welcome` → bar null (a reloaded page does not know the job's
plan; its old line shows until the result). `newLife(pcRef, settings, worldId = null)` sends `run_new
{pc_ref, settings}` (+ world_id when given, P12) and sets screen 'worldgen'; `cancelWorldgen()` sends
`worldgen_cancel`; `listPcs()` sends `pcs_list`.

## 6. Location description templates (`narration/location.py`)

Built by code from the PC's own view (the `describe` docstring is the exact contract):

Line 1 `{A/An} {size} {material} {kind}, {light}.` — size: "small" (< 15 m²), nothing (15–60 m²),
"long" (> 60 m² and one side at least twice the other) or "large"; material only indoors; light 0
"pitch dark", 1 "dim", 2 "low light", 3 "lit", 4 "bright". ("A large brick room, dim.")
Line 2 the weather as heard from here ("Wind pushes at the building.", "Rain falls steadily."), or
the room's own noise ("It is quiet.").
Line 3 (not in the dark) up to three notable anchors: "There are a counter, a gap behind the counter
and a front window here."
Line 4 known hazards/traces — "Glass on the floor near the door." (only traces the PC perceived; P10).
Line 5 occupancy — "You're alone." / "One other person is here." / "Four other people are here."
(people the PC can see, in its place).
Line 6 (not in the dark) cover — "The gap behind the counter would stop a bullet." (cover 3) /
"The shelves give some cover." (cover 2) / "The tall weeds would hide you." (concealment only).

Weather words (clock panel): clear Clear · overcast Overcast · rain Raining · storm Storm · fog Fog ·
wind Windy · heat Hot · snow Snowing. Noise words: < 45 dB quiet · < 70 some noise · < 95 noisy ·
else deafening (the loudest thing the PC heard this turn, or the room).
